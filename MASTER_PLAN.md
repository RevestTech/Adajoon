- **Bug fix (2026-11-15):** paid-tier subscribers (verified: a real "family" plan account) were still being shown the video ad preroll. Root cause: `useAds.js` decided ad-eligibility from the `useAuth()` user object's `subscription_tier` field — but neither `/api/auth/me` nor any login endpoint has ever returned that field, so it was always `undefined` and silently defaulted to `"free"`. The correct tier/status (`/api/subscriptions/status`, already fetched elsewhere via `useSubscription()`) was sitting right next to the broken check the whole time, just never consulted. Fixed by switching `useAds`/`shouldShowAds` to `useSubscription().isPremium()` instead. Verified end-to-end: set a real dev-login user's DB row to `tier=family, status=active`, confirmed `/api/subscriptions/status` reports it correctly, confirmed the fixed `isPremium()`/`shouldShowAds()` logic now returns "no ads" for that exact state (it returned "show ads" before the fix, matching the report). No backend change needed — this was purely the frontend reading the wrong source of truth.
- **Bug fix (2026-11-15): the site-wide rate limit was never actually enforced.** `app.state.limiter`/the `RateLimitExceeded` handler were set in `main.py`, but `SlowAPIMiddleware` itself — the piece that applies `limiter.py`'s `default_limits=["100/minute"]` to every route lacking its own `@limiter.limit(...)` — was never registered. So the default was computed but silently never applied; only the handful of routes carrying an explicit decorator were limited at all. Verified live before/after: hit an undecorated route (`/api/languages`) 105 times in a row — before the fix, all 105 returned 200; after, exactly 100 succeed and the rest 429. Also added the missing `10/minute` limit to 3 passkey endpoints (`register`, `login-options`, `login` — their sibling `register-options` already had one, but these didn't, unlike every other login route) and to the admin vault-secret write/delete endpoints. Added `backend/tests/test_rate_limiting.py` (structural check that the middleware is registered, plus a live check that the passkey fix actually trips a 429).

## Known tech debt / explicitly deferred
- **No uptime/reachability monitoring.** Nothing watches whether the public site actually responds — the 2026-11-09 domain incident was only caught because the user noticed manually. Needs an uptime check (e.g. UptimeRobot, Better Stack) hitting `adajoon.com` with alerts to a real destination. Not something this session can set up unilaterally (third-party account signup).
- Sentry is wired but has no DSN set — error tracking is currently a no-op until one is configured (Admin → Secrets → Sentry DSN, or `SENTRY_DSN`/`VITE_SENTRY_DSN`).
- No PR merged in this session had a true GitHub-enforced approval — the session's single GitHub identity can't self-approve its own PRs, so merges went through on CI/diff checks via direct API, not a review gate. Consider branch protection if a harder gate is wanted.
- Feature-gating enforcement is a no-op — tiers don't actually restrict anything but ad-removal. Real monetization gap, not just a dev one.
- No ad impression/fill-rate analytics.
- No audit logging, jobs-queue UI, or staging environment (deliberate, per team size — revisit if team/scale grows; the two 2026-11-08/09 incidents are evidence staging + monitoring may now be worth the cost).

## Mobile UX — 10-agent review (2026-11-14)
Found via 10 parallel read-only review agents (header/nav, filter bar, grid/list, player modals, touch targets, typography, bottom-stacking, settings/pricing, landing page, map/EPG, loading states) prompted by a user-reported screenshot of oversized/empty channel cards (that specific bug is already fixed, PR #109).

**Critical — fixed (PR #111):**
- Landing page (`LandingPage.jsx`/`.landing-page`) had `overflow: hidden` with no scroll fallback — on an iPhone with Safari + Apple login + passkeys, content could exceed the usable viewport with "Continue as guest"/Passkey pushed off-screen and unreachable. Fixed: `overflow-y: auto`.
- `SettingsPage.jsx`/`PricingPage.jsx`'s `.admin-modal-overlay`/`.admin-modal` had **zero CSS anywhere** — unstyled inline HTML, no backdrop/centering/scroll-clamp, unstyled close button. Fixed: real overlay/modal/close CSS, mirroring the existing `.modal-overlay`/`.modal-content` pattern; `.admin-close` sized to 44px.
- Filter bar (`.quality-filter`) had `flex-wrap: wrap` from the desktop rule, never reset to `nowrap` in the mobile override meant to turn it into a horizontal-scroll row — this was the cramped filter bar in the original screenshot. Fixed.
- EPG grid (`EpgGridView.jsx:114`) hardcoded the channel-column offset as `160px` for the "now" line, while CSS shrinks that column to `100px` on mobile — the time indicator rendered 60px off on phones. Fixed: both now read one `--epg-col` custom property, so they can't drift apart again.

**High — fixed (PR #111):**
- `.header-search`/`.search-input` had two of the three overlapping mobile media-query blocks fighting each other — a `@640px` block silently undid a `@768px` block's accessible sizing, shrinking the collapsed search box to 32px and its font to 12px (under the 16px that avoids iOS Safari's auto-zoom-on-focus). Fixed by removing the regressing duplicate. The remaining overlapping blocks for *other* selectors are untouched — full consolidation is still open, see below.
- Header icon buttons `.pricing-nav-btn`/`.whats-new-btn`/`.theme-toggle-btn` were 36px with no mobile override. Fixed: 44px at ≤640/860px.

**High — still open:**
- More touch targets under 44px: `.modal-close`, `.modal-favorite-btn`/`.modal-minimize`/`.modal-popout`/`.modal-share-btn` (player modal header, 36px), `.favorite-btn` gap at 481-768px (38px), `.world-map-zoom-btn`/`.world-map-zoom-reset` (shrinks the *wrong* way as screens narrow), radio map pins `.radio-garden-map__marker` (10×10px), pagination buttons, `.ai-search-btn`.
- List view (`.list-row`) has fixed-width columns never adjusted for mobile — the channel name column gets squeezed to almost nothing on a 375px screen.
- The header's three overlapping mobile media-query blocks (`@768px`, `@480px`, `@640px`) still need full consolidation into one block per selector — PR #111 only removed the one pair that was actively regressing search; the rest fight via `!important` with effectively-accidental results.
- `.back-to-top`/`.install-prompt` don't account for the mini-player being open, and don't add `env(safe-area-inset-bottom)` consistently.
- Skeleton loaders (`.skeleton-card`) don't match `.channel-card`'s sizing — layout jumps when real content loads.
- `.stream-switcher` has no `flex-wrap` for 3+ streams.
- `.channel-modal-header h3` has no overflow/ellipsis handling for long titles.

**Medium — still open:**
- Several text elements drop to 8-9px on mobile (`.channel-tag`, `.channel-stream-badge`, `.filter-group-label`, `.recent-item-name`).
- EPG channel names/programme titles are cramped at the mobile grid-column width.
- Redundant `.filter-group-label`s eat horizontal space in the filter-chip row.

## Mobile UX — design exploration (2026-11-14)
After the bug review, went further into forward-looking design, not just fixes:
1. Prototyped 5 new interaction patterns as a standalone interactive artifact (bottom tab bar, full-screen search, swipe-to-change-channel in the player, filters as a bottom sheet, pull-to-refresh), then iterated it into a fuller app-flow mockup (first-run picker, home rows, redesigned cards, a persistent mini-player, search-by-country) after review against real reference apps (Apple Music Radio, myTuner, generic radio-station apps).
2. Ran 20 parallel "expert opinion" agents across specific mobile-design topics (bottom sheets, gestures, dark mode, micro-interactions, loading states, card trends, typography, color/contrast, onboarding, empty states, search, player conventions, personalization, toasts, tab bars, settings screens, live indicators, maps, platform conventions, PWA install) and synthesized them into a ranked set of recommendations.
3. **Cross-checked the synthesis against the real codebase before building anything** — several of the recommended patterns already exist in some form and don't need new work: a persistent `MiniPlayer.jsx` (logo/name/play-pause/expand/stop), a `ForYouRow.jsx` ("For You in [category]", built from session analytics, no login needed), `QuickFilters.jsx` (verified/live/highly-rated chips), and country-based browsing (`Sidebar.jsx`'s country list, `activeCountries` filter state). The prototype's synthetic "no real artwork" card redesign also doesn't apply as-is — real channel/station cards already render actual logos (`channel.logo`/`station.favicon`).
4. What's still just a prototype, not implemented: full-screen search overlay, swipe left/right in the player to change channel/station, pull-to-refresh, long-press quick actions on a card, first-run country/genre picker, a "Continue watching/listening" row distinct from "For You", pure-black player background during playback, grouped settings sections. See the Adajoon mobile prototype artifact from this session for all of these working interactively. These are unstarted and need their own scoped PRs.
5. **Shipped for real:** search by country/name together (PR #111) — `search_channels`/`search_stations`' free-text query now also matches against the country's display name (via the `Country` table), not just channel/station name — so typing "Japan" surfaces Japanese channels without needing the Sidebar's separate click-to-pick-a-country list. Filters as a tap-to-open bottom sheet (PR #112) — on real phones (≤640px), the Verified/Live Now/Has Stream/etc. filter row now opens as a bottom sheet with a sticky "Show results" button instead of a horizontal-scroll strip (`MobileFilterSheet.jsx`, wrapping `ChannelGrid.jsx`/`RadioGrid.jsx`'s existing filter markup unchanged; tablets/desktop are untouched).
6. **Shipped for real:** bottom tab bar (`BottomTabBar.jsx`) — on real phones (≤640px), TV/Radio/Map/Movies now show as a persistent bottom row instead of the header's top icon strip, which is hidden at that width. It reuses the `--footer-bar-height` custom property that `.mini-player`/`.back-to-top` already measure themselves off, so they shift up above it automatically with no changes of their own; `.install-prompt` (previously hardcoded to `bottom: 16px`, one of the "High — still open" items above) was switched onto the same variable while here, so it no longer risks sitting under the tab bar or the mini-player either. Verified end-to-end against real seed data: tab switching across all 4 modes, the player modal still overlays everything correctly, and desktop/tablet (>640px) render byte-for-byte the same as before (the tab bar is `display: none` there, the header's icon row is untouched).
   - **Follow-up fix (same day):** a real-phone screenshot in Chrome/iOS showed the tab bar stacking with Chrome's own bottom toolbar (not installed as a PWA, so no `display-mode: standalone` to rely on) — two full nav rows at the bottom felt crowded. Fixed with the same pattern X/Instagram use on mobile web: `BottomTabBar.jsx` now hides on scroll-down and reappears on scroll-up (a capture-phase `scroll` listener on `document`, since scroll events don't bubble — this works regardless of which per-mode container is actually scrolling, with no need to track which one). Verified with simulated incremental scrolling (a single `scrollTop` jump doesn't exercise the delta logic; real touch/inertial scrolling fires many events, which it does correctly handle) — hides past a 40px buffer from the top, reappears within one scroll-up gesture.
