- **Bug fix (2026-11-15): the site-wide rate limit was never actually enforced.** `app.state.limiter`/the `RateLimitExceeded` handler were set in `main.py`, but `SlowAPIMiddleware` itself — the piece that applies `limiter.py`'s `default_limits=["100/minute"]` to every route lacking its own `@limiter.limit(...)` — was never registered. So the default was computed but silently never applied; only the handful of routes carrying an explicit decorator were limited at all. Verified live before/after: hit an undecorated route (`/api/languages`) 105 times in a row — before the fix, all 105 returned 200; after, exactly 100 succeed and the rest 429. - **Bug fix (2026-11-15): AI radio search always returned zero results.** `ai_search_radio` ran `int(station_id)` on the AI's matched ids to look them up, but `RadioStation.id` is a UUID string (Radio-Browser's `stationuuid`) - `int()` always raised, silently dropping every match, so the endpoint returned an empty station list regardless of what the AI actually found (and cached that empty response for 10 minutes). Fixed by using the string ids directly. Also fixed, same area: the sync `anthropic.Anthropic` client was being called from inside `async def` handlers for both TV and radio AI search, blocking the whole event loop for the full LLM round-trip - switched to `AsyncAnthropic`. Added `/api/search/ai`'s missing rate limit (`20/minute` - it hits the Claude API on a cache miss, reachable anonymously like the rest of search). Added `backend/tests/test_ai_search_radio.py`.

Fixed the 12 real pre-existing frontend test failures across 4 files (`useVotes.test.js` was testing a completely different, pre-rewrite localStorage-based hook API; `useAuth.test.js` referenced a removed `setUser` export and a stale `loading` expectation; `Header.test.jsx` used a text matcher that can't see text split across a child `<span>`; `useUrlState.test.js` expected unencoded commas and a phantom trailing `?` that the real implementation never produces) - same "surface and fix real failures first, then make the gate real" pattern as the original backend CI fix (#74). ESLint and the test step are now real, unconditional gates. mypy (never run before; ~180 pre-existing errors across ~57/61 files - the codebase has never been type-checked) and Prettier (no file has ever been run through it; 98/~110 files currently differ from its defaults) now actually run and their real output shows up as failed/yellow in the Actions UI via `continue-on-error: true`, rather than the previous `|| true`, which lied and reported silent green passes - but neither is a hard gate yet, since fixing either baseline is its own dedicated undertaking, not something to bundle into this fix.

## Mobile UX — 10-agent review (2026-11-14)
Found via 10 parallel read-only review agents (header/nav, filter bar, grid/list, player modals, touch targets, typography, bottom-stacking, settings/pricing, landing page, map/EPG, loading states) prompted by a user-reported screenshot of oversized/empty channel cards (that specific bug is already fixed, PR #109).

**Critical — fixed (PR #111):**
- Landing page (`LandingPage.jsx`/`.landing-page`) had `overflow: hidden` with no scroll fallback — on an iPhone with Safari + Apple login + passkeys, content could exceed the usable viewport with "Continue as guest"/Passkey pushed off-screen and unreachable. Fixed: `overflow-y: auto`.
- `SettingsPage.jsx`/`PricingPage.jsx`'s `.admin-modal-overlay`/`.admin-modal` had **zero CSS anywhere** — unstyled inline HTML, no backdrop/centering/scroll-clamp, unstyled close button. Fixed: real overlay/modal/close CSS, mirroring the existing `.modal-overlay`/`.modal-content` pattern; `.admin-close` sized to 44px.
- Filter bar (`.quality-filter`) had `flex-wrap: wrap` from the desktop rule, never reset to `nowrap` in the mobile override meant to turn it into a horizontal-scroll row — this was the cramped filter bar in the original screenshot. Fixed.
- EPG grid (`EpgGridView.jsx:114`) hardcoded the channel-column offset as `160px` for the "now" line, while CSS shrinks that column to `100px` on mobile — the time indicator rendered 60px off on phones. Fixed: both now read one `--epg-col` custom property, so they can't drift apart again.

**High — fixed (PR #111):**
- `.header-search`/`.search-input` had two of the three overlapping mobile media-query blocks fighting each other — a `@640px` block silently undid a `@768px` block's accessible sizing, shrinking the collapsed search box to 32px and its font to 12px (under the 16px that avoids iOS Safari's auto-zoom-on-focus). Fixed by removing the regressing duplicate. The remaining overlapping blocks for *other* selectors are untouched — full consolidation is still open, see below.
- Header icon buttons `.pricing-nav-btn`/`.whats-new-btn`/`.theme-toggle-btn` were 36px with no mobile override. Fixed: 44px at ≤640/860px.

**High — still open:**
- More touch targets under 44px: `.modal-close`, `.modal-favorite-btn`/`.modal-minimize`/`.modal-popout`/`.modal-share-btn` (player modal header, 36px), `.favorite-btn` gap at 481-768px (38px), `.world-map-zoom-btn`/`.world-map-zoom-reset` (shrinks the *wrong* way as screens narrow), radio map pins `.radio-garden-map__marker` (10×10px), pagination buttons, `.ai-search-btn`.
- The header's three overlapping mobile media-query blocks (`@768px`, `@480px`, `@640px`) still need full consolidation into one block per selector — PR #111 only removed the one pair that was actively regressing search; the rest fight via `!important` with effectively-accidental results.
- `.back-to-top`/`.install-prompt` don't account for the mini-player being open, and don't add `env(safe-area-inset-bottom)` consistently.
- Skeleton loaders (`.skeleton-card`) don't match `.channel-card`'s sizing — layout jumps when real content loads.
- `.stream-switcher` has no `flex-wrap` for 3+ streams.
- `.channel-modal-header h3` has no overflow/ellipsis handling for long titles.

**High — fixed (2026-11-15, user-reported with a real-phone screenshot):**
- List view (`.list-row`) had fixed-width columns (88px/100px, sized for desktop) never adjusted for mobile, squeezing the channel name into a sliver on a 375-430px screen; several text elements had also been shrunk as low as 8px on top of that (`.channel-stream-badge`, `.list-row-name`, `.list-meta-item`). Fixed: shrunk the status/vote columns at the 768px/480px breakpoints to give the name/meta column real room, raised the undersized text to a readable floor, and fixed a `.list-row-meta` overflow bug this surfaced (country/genre text was overlapping the status badge once given more room — now clips cleanly). Separately, radio's list view lost ALL of its metadata (country/genre/bitrate) on phones — a `.list-row-tags { display: none; }` rule at ≤480px was written assuming it only hid TV's secondary tag chips, but TV doesn't even use that class; `.list-row-tags` is radio's *only* metadata display. Fixed to keep the first chip (country code) instead of hiding everything.
- `.channel-card` (grid/card view) had no `min-width: 0`, so on a 2-up mobile grid (`repeat(2, 1fr)`) its default `min-width: auto` sized the card to fit `.channel-meta`'s chip row on one unwrapped line regardless of `flex-wrap: wrap` on the row itself - harmless for TV's short 1-2 chip meta row, but radio's denser one (country + up to 2 tags + bitrate + status badge, often 4-5 chips) forced the card wider than its grid column and visibly spilled into the next card. Fixed with `min-width: 0` on `.channel-card`; verified both TV and radio card view at a real phone viewport, plus desktop, with no regression.
- Checked the Map view's two sub-modes too. TV Channels (`WorldMap.jsx`) sizing/legibility was fine on a real phone viewport, but its country-paths dataset (`worldMapPaths.js`) has two disjoint landmasses sharing one entry each - Cyprus/N. Cyprus both `id: "CY"`, Somalia/Somaliland both `id: "SO"` - which fed a duplicate `key` into React's `.map()` (console warning, and an invalid duplicate DOM `id` on the rendered `<path>`s). Fixed by keying on `id-name` instead and renaming the SVG attribute from `id` to `data-country-code` (nothing read the DOM `id`, so this was free). Radio Stations sub-mode (`RadioGardenMap.jsx`) had a real mobile-only overlap: the floating "Take a ride" button's `bottom: 16px` put it directly on top of the maplibre attribution strip, which spans nearly the full width below 768px instead of hugging the right edge like on desktop - confirmed no desktop regression, since there the attribution sits far enough right of the centered button to begin with. Fixed by raising the mobile bottom offset to clear it (measured gap, not guessed).
- User-reported (screenshot): collapsing the sidebar via "Hide filters" left a big blank gap instead of actually shrinking, at some window sizes. Root cause was a CSS cascade bug, not a JS one: the Tablet breakpoint (`@media (max-width: 1024px)`) unconditionally reset `.sidebar { width: var(--sidebar-width) }`, and since it's declared *after* the collapse rule (`@media (min-width: 769px) { .sidebar--rail-collapsed { width: 0 } }`) with the exact same selector specificity, it won the cascade whenever both conditions were true (769-1024px CSS viewport width - e.g. a normal-looking browser window on a Retina display, since that's CSS px, not physical px). Net effect: `.sidebar-body`'s `display: none` still applied (that selector's higher specificity wasn't affected), but the panel itself stayed at its full 300px width - a blank, content-less gap exactly where the sidebar used to be. Fixed by scoping the Tablet rule to `.sidebar:not(.sidebar--rail-collapsed)` so it can no longer fight the collapsed state regardless of source order. Verified the full matrix with Playwright: desktop expand/collapse (380px/0px), tablet width expanded (300px, unchanged) and collapsed (0px, previously broken, now fixed), and mobile (untouched - drawer mode doesn't use this toggle at all).

**High — fixed (2026-11-20, user-reported with a real-phone screenshot):**
- The mobile "Filters" bottom sheet (`MobileFilterSheet.jsx`, ≤640px) rendered its status/community chips (`.quality-btn` - All/Verified/Live Now/Has Stream/Highly Rated/Hide Broken) at 10-11px, visibly smaller than the "Show results" button (14px) in the same sheet. Root cause: the sheet reuses the same `.quality-btn` markup as the cramped horizontal-scroll filter row on tablet, so it inherited that row's small-screen-real-estate-driven font sizing (11px at ≤768px, 10px at ≤480px) even though the sheet itself is full-width and wraps, with no space constraint to justify it. Fixed with a `.filter-sheet-body .quality-btn { font-size: 14px }` override - wins on specificity (two classes beat one) regardless of source order, so it holds at every phone width the sheet shows, without touching the horizontal-scroll row's intentionally compact sizing on tablet.

**Medium — still open:**
- Several other text elements still drop to 8-9px on mobile (`.channel-tag` outside list view, `.filter-group-label`, `.recent-item-name`) - the list-view-specific instances above are fixed, this is the remaining surface.
- EPG channel names/programme titles are cramped at the mobile grid-column width.
- Redundant `.filter-group-label`s eat horizontal space in the filter-chip row.

## Mobile UX — design exploration (2026-11-14)

1. Prototyped 5 new interaction patterns as a standalone interactive artifact (bottom tab bar, full-screen search, swipe-to-change-channel in the player, filters as a bottom sheet, pull-to-refresh), then iterated it into a fuller app-flow mockup (first-run picker, home rows, redesigned cards, a persistent mini-player, search-by-country) after review against real reference apps (Apple Music Radio, myTuner, generic radio-station apps).
2. Ran 20 parallel "expert opinion" agents across specific mobile-design topics (bottom sheets, gestures, dark mode, micro-interactions, loading states, card trends, typography, color/contrast, onboarding, empty states, search, player conventions, personalization, toasts, tab bars, settings screens, live indicators, maps, platform conventions, PWA install) and synthesized them into a ranked set of recommendations.
3. **Cross-checked the synthesis against the real codebase before building anything** — several of the recommended patterns already exist in some form and don't need new work: a persistent `MiniPlayer.jsx` (logo/name/play-pause/expand/stop), a `ForYouRow.jsx` ("For You in [category]", built from session analytics, no login needed), `QuickFilters.jsx` (verified/live/highly-rated chips), and country-based browsing (`Sidebar.jsx`'s country list, `activeCountries` filter state). The prototype's synthetic "no real artwork" card redesign also doesn't apply as-is — real channel/station cards already render actual logos (`channel.logo`/`station.favicon`).
4. What's still just a prototype, not implemented: full-screen search overlay, swipe left/right in the player to change channel/station, pull-to-refresh, long-press quick actions on a card, first-run country/genre picker, a "Continue watching/listening" row distinct from "For You", pure-black player background during playback, grouped settings sections. See the Adajoon mobile prototype artifact from this session for all of these working interactively. These are unstarted and need their own scoped PRs.
5. **Shipped for real:** search by country/name together (PR #111) — `search_channels`/`search_stations`' free-text query now also matches against the country's display name (via the `Country` table), not just channel/station name — so typing "Japan" surfaces Japanese channels without needing the Sidebar's separate click-to-pick-a-country list. Filters as a tap-to-open bottom sheet (PR #112) — on real phones (≤640px), the Verified/Live Now/Has Stream/etc. filter row now opens as a bottom sheet with a sticky "Show results" button instead of a horizontal-scroll strip (`MobileFilterSheet.jsx`, wrapping `ChannelGrid.jsx`/`RadioGrid.jsx`'s existing filter markup unchanged; tablets/desktop are untouched).
6. **Shipped for real:** bottom tab bar (`BottomTabBar.jsx`) — on real phones (≤640px), TV/Radio/Map/Movies now show as a persistent bottom row instead of the header's top icon strip, which is hidden at that width. Verified end-to-end against real seed data: tab switching across all 4 modes, the player modal still overlays everything correctly, and desktop/tablet (>640px) render byte-for-byte the same as before (the tab bar is `display: none` there, the header's icon row is untouched).
